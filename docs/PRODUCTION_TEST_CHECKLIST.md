> 仅在你拥有授权的测试环境执行。高危操作不要直接对生产库做。
> 建议使用独立 Supabase 项目、独立测试域名、独立测试账号和测试 APK。

## 2. 注册、登录、会话

### 2.1 正常流程

- [ ] H5：打开注册，完成 Turnstile，填写合法资料，注册成功。
- [ ] App：打开注册，填写资料，提交时自动完成安全验证，注册成功。
- [ ] 注册成功页显示 12 位学号。
- [ ] 复制学号成功。
- [ ] 必须再次输入完整学号并勾选确认才能进入。
- [ ] 用新学号 + 密码登录成功。
- [ ] 登录后进入主页，不出现多次 bridge 页面跳转。
- [ ] 退出登录后回到登录页。
- [ ] 杀掉 App 后重新打开，会话按预期恢复或要求登录。
- [ ] 关闭 H5 页面后重新打开，会话按预期恢复。
- [ ] access token 过期后自动刷新。
- [ ] 刷新 token 失效后回到登录页。

### 2.2 非常规输入

- [ ] 学号 11 位、13 位、含字母、含空格、全角数字、前导 0。
- [ ] 学号 `000000000000`。
- [ ] 密码 7 位、8 位、全字母、全数字、含空格、含中文、含 emoji、64/65 位。
- [ ] 姓名 1 个字符、2 个字符、50 个字符、51 个字符。
- [ ] 姓名包含中文、空格、`·`、`-`、emoji、RTL、零宽字符。
- [ ] 姓名包含控制字符。
- [ ] 姓名包含 `<script>alert(1)</script>`、`<img src=x onerror=alert(1)>`。
- [ ] 姓名包含 `' OR 1=1 --`、`"; DROP TABLE profiles; --`。
- [ ] 姓名只包含空白字符。
- [ ] 重复注册同一学号。
- [ ] 直接调用 `/auth/v1/signup`，尝试跳过前端 Turnstile。
- [ ] 错误密码连续登录，观察限流/提示。
- [ ] 登录时关闭网络、切换到飞行模式、恢复网络。
- [ ] 收到 429 后等待并重试是否恢复。

### 2.3 会话安全

- [ ] 篡改 JWT payload（改 user id/role）后请求，必须 401。
- [ ] 篡改 JWT 签名后请求，必须 401。
- [ ] 使用过期 access token，必须失败或刷新。
- [ ] 使用 refresh token 冒充 access token，必须失败。
- [ ] 退出后旧 access token 继续调用业务 RPC，必须失败或受最短有效期约束。
- [ ] H5 localStorage 中不出现明文密码、密码盐以外的敏感信息。
- [ ] 注销账号后旧 token 不能继续访问。

### 12.8 可直接执行的请求样例

以下命令只用于测试环境，替换占位符后执行。

```bash
# 1) 匿名读 profiles
curl -i "$SUPABASE/rest/v1/profiles?select=*" \
  -H "apikey: $ANON" \
  -H "Authorization: Bearer $ANON"

# 2) 匿名读签到密钥
curl -i "$SUPABASE/rest/v1/checkin_secrets?select=*" \
  -H "apikey: $ANON" \
  -H "Authorization: Bearer $ANON"

# 3) 匿名调用业务 RPC
curl -i "$SUPABASE/rest/v1/rpc/list_checkin_events" \
  -H "apikey: $ANON" \
  -H "Authorization: Bearer $ANON" \
  -H "Content-Type: application/json" \
  -d '{"p_scope":"ended","p_status":"all"}'

# 4) A 读取 B 的签到记录
curl -i "$SUPABASE/rest/v1/checkin_records?select=*&user_id=eq.$USER_B" \
  -H "apikey: $ANON" \
  -H "Authorization: Bearer $JWT_A"

# 5) 已登录用户尝试直接改表
curl -i -X PATCH "$SUPABASE/rest/v1/profiles?id=eq.$USER_B" \
  -H "apikey: $ANON" \
  -H "Authorization: Bearer $JWT_A" \
  -H "Content-Type: application/json" \
  -d '{"full_name":"attacker"}'

# 6) 用 A 的 token 调创建签到 RPC，传 B 的班级
curl -i "$SUPABASE/rest/v1/rpc/create_checkin_event" \
  -H "apikey: $ANON" \
  -H "Authorization: Bearer $JWT_A" \
  -H "Content-Type: application/json" \
  -d '{"p_class_id":"<B 的班级 uuid>","p_title":"test","p_description":"test description","p_timezone":"Asia/Shanghai","p_start_at":"2026-01-01T00:00:00Z","p_end_at":"2026-01-01T01:00:00Z"}'

# 7) 代理/Worker 路径穿越
curl -i "https://<worker-host>/checkin-api?path=%2Frest%2Fv1%2F..%2F..%2Fauth%2Fv1%2Fadmin"

# 8) 注入 payload 通过业务 RPC
curl -i "$SUPABASE/rest/v1/rpc/create_class" \
  -H "apikey: $ANON" \
  -H "Authorization: Bearer $JWT_A" \
  -H "Content-Type: application/json" \
  -d '{"p_name":"x'\'' OR 1=1 --","p_validity_seconds":3600,"p_captcha_ticket":"<ticket>"}'
```

预期：

- 只能得到 401/403/404，或 RLS 允许范围内的空数组。
- 任何情况下不能返回其他用户的资料、签到密钥、记录或申请。
- 不能因为注入 payload 产生 SQL 错误详情。
- 路径穿越必须返回 403。
- 所有拒绝响应不包含数据库错误栈、密钥、JWT、内部路径。
