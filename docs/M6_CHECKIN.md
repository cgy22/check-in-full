# M6 签到流程

## 首页和详情

- 首页调用 `get_home_checkins` 一次读取正在签到、未开始、已结束三组活动。切换页签和已结束筛选使用内存缓存，下拉刷新重新请求。
- 登录、注册、退出、注销和发布签到会清空首页缓存。详情页调用 `get_checkin_event` 获取活动、本人记录、人数、服务端时间和角色可用的签到码，再更新首页对应卡片。
- 活动开始前可以查看应签到人员，开始后创建者可以手动调整成员状态或提前结束。创建者不参与该场签到。
- 已结束且未签到的适用成员可从详情页申请补签。 [补签申请与审批](M7_APPEALS.md)

## 动态码与学生提交

1. 创建者从开始前 5 分钟起可以获取签到码，活动结束后停止提供。`get_checkin_code` 按服务器的 30 秒时间片生成六位数字。二维码包含同样的数字。
2. 详情页显示倒计时。到期后使用「刷新签到码」或下拉刷新获取新码。人数在刷新详情时更新。
3. 学生输入六位数字或扫码后自动提交。Android 使用 `uni.scanCode`，H5 使用浏览器支持的 `BarcodeDetector`。允许数字签到的活动可用手输。
4. `submit_checkin` 核对参与资格、服务器时间、方式和选配的定位或设备要求，然后验证六位码摘要。每个时间片允许 5 次验证码错误。用上一时间片成功时显示“上一轮码”。
5. 签到结果记录在 `vu_records`。同一学生同一活动只能形成一条签到记录，重复提交会提示已经签到。

## 联调

- 使用两个账号核对创建者和参与者视图、二维码与数字一致性、上一轮码标记和同一轮失败次数限制。
- 分别核对仅数字、仅二维码、两者并用的活动。位置校验用开启和关闭两种活动测试，设备绑定用两台设备核对。
- 详情页刷新后与首页卡片、应签名单、签到结果中的计数应一致。 [发布验收与测试清单](PRODUCTION_TEST_CHECKLIST.md)
